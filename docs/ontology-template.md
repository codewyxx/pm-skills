# 业务本体模板（Ontology Template）

> **是什么**：把分散的先例（采集文档、字段方案、实体梳理）抽象成可迁移的语义模型——实体、关系、状态机、口径、权限、通用变更模式。
> **为什么**：先例回答「上次怎么做的」（绑定环境，不可复制），本体回答「这个系统是什么」（可迁移，可推理）。先例是证据，本体是结论。
> **三层知识体系**：Skill＝怎么做（程序知识，跨环境复用）；本体＝是什么（语义知识，常驻上下文）；先例＝为什么（叙事知识，按需检索）。本体不能代替先例——决策推理、被否方案、证据链只在先例里。

## 置信度标记

| 标记 | 含义 |
|---|---|
| ● | 实证：页面/接口/权限中直接出现 |
| ○ | 推断：由字段、动作或链路必然推出，未直接看到 |
| ※ | 冲突或存疑：两处口径不一致，需确认 |

---

## 1. 实体层

**识别原则**：一个实体 = 一个可被唯一标识、独立演进的数据对象；页面上的一列字段不算实体。

**类型四分法**：

| 类型 | 定义 | 示例（通用 B 端） |
|---|---|---|
| `主体` | 长期存在的主数据 | 商家、买家、商品、订单 |
| `单据` | 一次业务行为产生、有生命周期 | 审核单、退款单、触达记录 |
| `配置` | 有版本、有效力 | 佣金规则、频道配置 |
| `关系`/`派生` | 连接两实体 / 统计视图 | 绑定关系 / 渠道统计 |

**两条建模铁律**：审核类必成独立单据（不揉进主体表）；统计类不成实体，只挂口径。

**枢纽实体识别**：被 ≥5 个模块外键引用的主数据是枢纽，任何变更先评估对它的影响。

## 2. 关系层

画法：实体间标注基数（1:N、N:M）与引用方向；派生视图只挂口径来源，不进关系图。

## 3. 状态机层（三个通用模式）

### 3.1 审核流 `AuditTask`

```
待初审 → 初审驳回(终)
   └→ 待复审 → 复审驳回(终)
        └→ 已通过(终) → 自动生效
```

通用字段：`entityType, entityId, 操作类型, 阶段, 结果, 原因, 初审意见, 复审意见`。凡「初审→复审」结构都可归并为本模型，避免每模块重复造轮子。

### 3.2 主单据生命周期

按业务主链路梳理（如订单：待支付 → 待履约 → 履约中 → 售后窗口 → 已完成 + 异常分支）。

### 3.3 配置发布流 `ConfigVersion + PublishTask`

```
草稿 → 已发布（当前版本）→ 新草稿覆盖 →（定时|立即）发布
```

「线上状态/变更状态分离」与「当前/草稿/已发布」是同一机制的不同表述，应统一。

## 4. 口径字典

> 新增字段先查字典，命中即复用，防止同名字段多种算法。

每条目 = **定义 + 包含/排除 + 空值规则 + 更新时机 + 数据源 + 证据**。

| 示例条目 | 定义 | 包含/排除 | 空值展示 |
|---|---|---|---|
| 在售商品数 | 商家累计发布商品总数 | 含各状态，不含物理删除 | 显示「0」，不显示「-」 |
| 认证时间 | 最近一次实名认证通过时间 | 仅已认证有值，重新认证覆盖 | 未认证显示「-」 |

## 5. 权限语法

通用形式 `{实体}:{动作}`，动作收敛为六类：`view` / `create·edit·delete` / `status` / `review·secondary_review` / `import·export` / 特殊动作。

**必做校验**：菜单 ↔ 权限资源一一映射——有权限无菜单（隐藏功能）、有菜单无权限（失控入口）都要标记 ※。

## 6. 通用变更模式（示例：模式 P1）

> ≥2 条同构先例才可抽象为模式。**单样本不抽象，只记录。**

**模式 P1 · 列表页新增字段/筛选，九个必填槽位**：

| # | 槽位 | 必须回答 |
|---|---|---|
| 1 | 口径 | 统计/取数定义、包含排除 |
| 2 | 空值规则 | 显示 0 还是「-」 |
| 3 | 更新时机 | 实时统计 / 快照 |
| 4 | 列位置 | 语义分组是否被打断 |
| 5 | 排序/筛选 | 是否支持，默认序是什么 |
| 6 | 导出同步 | 列对齐 / 格式 / 脱敏沿用 |
| 7 | 一致性 | 与哪个既有页面同口径 |
| 8 | 影响隔离 | 哪些 Tab/页面**不**变 |
| 9 | 待确认项 | 留给评审拍板的开放问题 |

## 7. 边界规则

| 能抽象 | 不能抽象（需新证据） |
|---|---|
| 实体识别与归域 | 基数与性能约束（数据量级） |
| 通用状态机（枚举证据充分时） | 完整字段级数据字典（先例覆盖不足时） |
| 有先例支撑的字段口径 | 未采集端（如 C 端）的行为流 |
| 权限语法模式 | 接口级契约（需请求/响应体证据） |

## 8. 回填机制

1. 每完成一个需求，先例文档末尾附**语义卡片**（实体/口径/状态/权限四栏，见 [precedent-template.md](precedent-template.md)）
2. 评审通过后，新条目合并进本体对应章节
3. 本体文件维护版本记录（版本/日期/变更说明）

**先例喂本体，本体反哺先例去重。**
