# Verification Before Completion (`verification-before-completion`)

> 在声称完成、修复或通过之前，运行验证命令并检查输出，用证据代替断言。

| 维度 | 说明 |
|---|---|
| 分类 | 计划与工程执行 |
| 阶段 | 完成前验证 |
| 主要使用者 | 开发、测试、技术负责人 |
| 输出 | 验证证据和明确的完成/未完成结论 |

## 1. 能力

定义完成所需的验证命令；实际运行而不是推测；读取完整输出；确认需求、测试和边界；没有证据时明确说未验证。

## 2. 定位

**它负责：**

- 定义完成所需的验证命令
- 实际运行而不是推测
- 读取完整输出
- 确认需求、测试和边界
- 没有证据时明确说未验证。

**它不负责：**

- 替代测试用例设计
- 替代代码审查
- 替代产品验收和用户确认
- 在失败输出上继续宣称完成

## 3. 适用场景

- 准备提交代码、创建 PR 或宣布完成
- 修复 bug 后需要证明问题消失
- 需要检查测试、构建、lint 或运行时结果
- 需要区分已验证和未验证的部分

## 4. 示例

**用户输入：**

```text
准备提交这批修改。请运行测试、构建和关键回归命令，确认结果后再给出完成结论。
```

**Skill 的执行方式：**

1. 列出完成所需的验证命令
2. 逐项执行并保存输出
3. 检查失败和警告
4. 确认需求与测试对应
5. 总结已验证和未验证内容
6. 只有在证据充分时才宣布完成

**产出：**

命令、输出摘要、通过和失败项、剩余风险以及完成声明。

## 5. 输入与输出

| 项目 | 说明 |
|---|---|
| 输入 | 变更内容、需求、测试命令、构建命令和预期结果 |
| 输出 | 验证证据和明确的完成/未完成结论 |
| 主要产物 | 验证记录 |
