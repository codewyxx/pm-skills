# PRD (`prd`)

> 把已确认的产品方向和 brief 展开为结构化 PRD，覆盖用户故事、功能需求、验收标准、技术约束、风险和路线图。

| 维度 | 说明 |
|---|---|
| 分类 | 产品经理工作流 |
| 阶段 | 产品需求定义 |
| 主要使用者 | 非产品经理、产品负责人 |
| 输出 | 结构化 PRD 和可测试的验收标准 |

## 1. 能力

把模糊描述转成可测试的需求；补全用户故事和验收标准；区分功能需求、技术约束和 AI 能力要求；显式列出非目标和风险；为研发和测试提供单一需求来源。

## 2. 定位

**它负责：**

- 把模糊描述转成可测试的需求
- 补全用户故事和验收标准
- 区分功能需求、技术约束和 AI 能力要求
- 显式列出非目标和风险
- 为研发和测试提供单一需求来源。

**它不负责：**

- 替代 product-brief 做问题发现
- 替代 solution-design 做技术架构
- 替代 test-design 做测试方案
- 在需求和范围还没有确认时直接堆字段

## 3. 适用场景

- 已有 brief，需要展开完整 PRD
- 需求涉及多个角色、多个流程或 AI 能力
- 研发和测试需要统一的需求基线
- PRD 评审前需要检查需求是否可测试

## 4. 示例

**用户输入：**

```text
基于已批准的批量提醒 brief，写一份 PRD。需要覆盖运营角色、批量选择、发送结果、异常情况、权限和验收标准。
```

**Skill 的执行方式：**

1. 读取 brief 和后台业务规则
2. 补全用户故事和场景
3. 逐条定义功能需求和边界
4. 写验收标准、非目标和风险
5. 检查需求是否可测试、是否存在隐藏逻辑
6. 输出 PRD 并交给产品评审和下游交接

**产出：**

`04-prd.md`，包含执行摘要、用户体验与功能、AI 要求（如适用）、技术约束与集成、风险与路线图。

## 5. 输入与输出

| 项目 | 说明 |
|---|---|
| 输入 | 已确认的 brief、业务规则、用户场景、约束和现有系统上下文 |
| 输出 | 结构化 PRD 和可测试的验收标准 |
| 主要产物 | `docs/product/<feature-slug>/04-prd.md` |
