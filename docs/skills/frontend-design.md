# Frontend Design (`frontend-design`)

> 为新建或重塑的界面提供有意图的视觉方向、排版、色彩、版式和自我批判流程，避免生成模板化页面。

| 维度 | 说明 |
|---|---|
| 分类 | 界面设计 |
| 阶段 | 视觉方向与前端实现 |
| 主要使用者 | 前端开发、设计、产品负责人 |
| 输出 | 视觉设计计划、设计 token 和前端实现 |

## 1. 能力

从主题和使用场景提炼视觉语言；制定颜色、字体、布局和设计原则；避免常见 AI 生成审美；在实现时保持可访问性、响应式和视觉一致性。

## 2. 定位

**它负责：**

- 从主题和使用场景提炼视觉语言
- 制定颜色、字体、布局和设计原则
- 避免常见 AI 生成审美
- 在实现时保持可访问性、响应式和视觉一致性。

**它不负责：**

- 产品需求、用户旅程和业务规则设计
- 后台权限、状态、批量操作和导出规则；使用 admin-product-design
- 替代 UX 研究和可用性测试
- 只做组件库实现或纯 CSS 修复

## 3. 适用场景

- 新页面需要明确的视觉识别
- 现有界面看起来模板化，需要重塑
- 需要在编码前形成色彩、字体和布局方向
- 需要从设计角度审查前端实现

## 4. 示例

**用户输入：**

```text
为内部运营后台做一个有辨识度的数据总览页，但不要使用常见的 SaaS 卡片堆叠和默认渐变。
```

**Skill 的执行方式：**

1. 确认主题、受众和页面任务
2. 提出 4-6 个色彩 token、字体角色和布局概念
3. 审查方案是否落入模板化默认
4. 实现界面并保持可访问性和响应式
5. 截图或检查结果后进行自我批判和收敛

**产出：**

颜色、排版、布局和视觉原则说明，以及按该方向实现的前端页面。

## 5. 输入与输出

| 项目 | 说明 |
|---|---|
| 输入 | 产品主题、用户、页面任务、已有品牌或视觉约束、前端技术栈 |
| 输出 | 视觉设计计划、设计 token 和前端实现 |
| 主要产物 | 视觉设计计划和前端界面 |
