# Writing Plans (`writing-plans`)

> 在需求和设计已经明确后，把工作拆成文件级、步骤级、可验证的实施计划。

| 维度 | 说明 |
|---|---|
| 分类 | 计划与工程执行 |
| 阶段 | 实施计划 |
| 主要使用者 | 开发、技术负责人 |
| 输出 | 可执行的实施计划文档 |

## 1. 能力

明确要创建和修改的文件；把任务拆成带测试和验证的步骤；写清接口、依赖和提交点；为独立执行者提供足够上下文。

## 2. 定位

**它负责：**

- 明确要创建和修改的文件
- 把任务拆成带测试和验证的步骤
- 写清接口、依赖和提交点
- 为独立执行者提供足够上下文。

**它不负责：**

- 产品发现、产品策略或用户研究
- 技术架构设计和 API 决策
- 测试策略和测试用例设计
- 在需求仍模糊时直接排开发任务

## 3. 适用场景

- 已有批准 PRD 或技术方案，需要拆实施计划
- 任务需要交给另一个工程师或子代理执行
- 需要明确文件、步骤、测试和提交顺序
- 实施过程中需要可检查的进度单位

## 4. 示例

**用户输入：**

```text
基于已批准的技术方案，把批量提醒功能拆成可执行计划。每个任务必须包含要改的文件、测试命令、预期失败和通过标准。
```

**Skill 的执行方式：**

1. 读取需求和设计
2. 映射文件结构和接口
3. 按可独立验证的交付物拆任务
4. 为每个任务写测试、实现、验证和提交步骤
5. 做自查并输出计划

**产出：**

`docs/superpowers/plans/YYYY-MM-DD-<feature-name>.md`，包含目标、架构、技术栈、全局约束、任务和验收步骤。

## 5. 输入与输出

| 项目 | 说明 |
|---|---|
| 输入 | 已批准的 PRD、技术方案、代码库上下文和项目约定 |
| 输出 | 可执行的实施计划文档 |
| 主要产物 | `docs/superpowers/plans/YYYY-MM-DD-<feature-name>.md` |

## 6. 文件结构

所有 Skill 都以 `SKILL.md` 为运行时入口；`assets/` 放模板，`references/` 放按需加载的参考文档，`scripts/` 放可执行辅助脚本。

| 文件 | 目的 |
|---|---|
| [`SKILL.md`](../../skills/product/writing-plans/SKILL.md) | 计划结构、任务粒度、步骤格式、自查和交接要求 |
