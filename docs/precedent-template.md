# 先例文档模板 + 语义卡片

> **先例的定位**：记录一次需求「当时怎么决策的」——决策推理、被否方案、待确认项。它是本体的证据库，按 [ontology-template.md](ontology-template.md) 的回填机制反哺本体。
> **使用方式**：需求交付时按 §1 结构写先例，末尾按 §2 附语义卡片。

## 1. 先例文档结构

```markdown
# <页面>新增<字段/功能>方案

## 变更概览
- 变更页面：<模块 → 页面>
- 新增/变更点：<一句话>
- 位置与顺序：<前后对比>
> 原型图 / 可编辑源文件链接

## 一、字段（或功能）说明
| 项目 | 说明 |
|---|---|
| 字段含义 | |
| 统计口径 / 数据口径 | 含什么、不含什么 |
| 展示规则 | 格式、空值显示 |
| 取值更新 | 实时 / 快照 / 覆盖规则 |
| 一致性 | 与哪个既有页面/弹窗同口径 |

## 二、交互与导出变更
1. 导出范围是否变化
2. 导出列与列表列的对齐
3. 脱敏规则沿用
4. 明确「本次不变」的范围（影响隔离）

## 三、待确认事项
1. <留给评审拍板的开放问题>

## 四、语义卡片（见下）
```

**要点**：待确认项必写——这是审校判断的落点，也是先例最有迁移价值的部分（记录"当时悬而未决什么"）。

## 2. 语义卡片（先例 → 本体的接口）

每个先例末尾附四栏卡片，评审通过后条目合并进本体：

| 栏 | 写什么 | 示例 |
|---|---|---|
| 实体 | 涉及哪些业务对象（新建/引用） | 引用：商家、商品 |
| 口径 | 新增或复用的口径条目 | 新增：在售商品数（含全状态，不含物理删除） |
| 状态 | 涉及的状态机与流转 | 商品状态机：待审核→上架中→已下架/已驳回 |
| 权限 | 查看/操作/数据范围三层 | 运营全量可见；导出沿用既有权限 |

## 3. 完整脱敏示例

> 以下为虚构示例，演示结构，不指向任何真实系统。

# 商家列表新增「在售商品数量」字段方案（示例）

## 变更概览
- 变更页面：商家管理 → 商家列表
- 新增列表字段（1 个）：「在售商品数量」，位于「主营类目」与「认证状态」之间
- 筛选区不新增；新列不支持排序，维持入驻时间倒序

## 一、字段说明

| 项目 | 说明 |
|---|---|
| 字段含义 | 该商家累计发布过的商品总数 |
| 统计口径 | 全部状态计数：含待审核、在售、已下架、已驳回；不含物理删除 |
| 展示规则 | 整数；数量为 0 显示「0」，不显示「-」 |
| 取值更新 | 随列表查询实时统计，不做快照 |
| 一致性 | 与商品列表按该商家筛选后的总条数口径一致 |

## 二、导出变更

导出列与列表完全对齐新增一列；整数格式；0 导出为「0」；流程与条数上限沿用现状；仅作用于商家列表 Tab。

## 三、待确认事项

1. 待审核商品是否计入（当前计入，若业务只认「审核通过」需调整口径）
2. 是否需要点击穿透到商品列表（当前纯展示）

## 四、语义卡片

| 栏 | 内容 |
|---|---|
| 实体 | 引用：商家（Merchant）、商品（Product）；关系：Merchant 1:N Product |
| 口径 | 新增「在售商品数」：全状态计数，不含物理删除；空值显示「0」 |
| 状态 | 商品状态机：待审核 → 在售 → 已下架 / 已驳回（终态） |
| 权限 | 运营全量可见；导出权限沿用列表导出权限 |
